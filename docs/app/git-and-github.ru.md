# История версий и резервная копия

Ваша база знаний — это папка, поэтому она может быть git-репозиторием, что даёт
вам полную историю каждого изменения и способ приватного резервного копирования.

Это полностью опционально. Всё работает и без этого.

## Что это даёт

- **Отмена, которая переживает всё.** Не только последнее изменение — любой файл
  в любой момент прошлого.
- **Запись о том, что изменилось и когда**, включая всё, что сделал агент.
- **Резервное копирование и синхронизация** через приватный репозиторий GitHub.

## Начало работы

Попросите агента «настроить контроль версий для этой папки», и он сделает
всё целиком. Или воспользуйтесь значком git в левой панели.

Чтобы делать резервные копии на GitHub, нужен токен — пароль с ограниченным
доступом. В «Настройки → Git и GitHub» есть точные шаги, и главное в том, что его
можно ограничить **только этим одним репозиторием**.

Когда всё настроено, попросите «опубликовать это в приватный репозиторий GitHub».

## Коммит — всегда только по вашей просьбе

Агент никогда не делает коммитов сам, сколько бы файлов он ни изменил. Он
делает коммит, когда вы просите, рассказывает, что туда вошло, и не будет молча
упаковывать несвязанные изменения вместе.

Панель **Изменения агента** показывает, что было отредактировано с тех пор, как
вы последний раз смотрели, так что можно проверить перед решением.

## Что стоит знать

- **Синхронизация только движется вперёд.** Если та же папка изменилась в двух
  местах, приложение не будет пытаться слить изменения — вы решаете это в терминале.
  На практике для личной базы знаний это редкость.
- **Индексы документов и файлы больше 100 МБ пропускаются** при отправке. Индексы
  перестраиваются сами, поэтому ничего не теряется, а репозиторий остаётся маленьким.
- **Изображения и PDF коммитятся как обычно.**
- **Восстановление отбрасывает незакоммиченную работу**, поэтому агент сначала
  попросит подтверждения.
